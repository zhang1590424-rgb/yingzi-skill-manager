# 影子重构：技能组合选择器化 + `.agents` 目录收敛设计

## 1. 背景与问题

当前「影子」基于「多 Agent 技能分发器」模型，存在两个核心痛点：

### 痛点 1：组合与单技能两套粒度并存，频繁冲突

「技能组合」和「单技能」是两套独立的可应用对象，各自有状态、各自能应用/收回。同一个技能既能被组合应用、又能被单独应用，导致：

- **重复管理混乱**：搞不清某个技能到底通过谁应用、该从哪收回。
- **组合内外状态打架**：组合显示「部分应用」，但成员单技能显示「已应用」，聚合状态与单体状态互相矛盾。
- **软链接技术冲突**：目标位置已有同名内容或指向别处的软链接，被标记为「冲突」需手动处理。

根因是**两套粒度并存**，状态相互独立又相互影响。

### 痛点 2：多 Agent 分发模型过度复杂

当前每个项目下要按 Agent 拆成 5 套目录（`.codex/skills`、`.trae-cn/skills`、`.claude/skills`、`.aiden/skills`、`.agents/skills`），全局同理。用户实际只用兼容 `.agents` 目录的工具（Codex、Trae CN 等），每次应用都要逐个选 Agent，是无意义的负担。

**事实核查（2026-06-19）**：

| 工具 | 项目级技能目录（官方/实测） | 现有代码写的 | 备注 |
| --- | --- | --- | --- |
| Codex | `.agents/skills` | `.codex/skills`（错） | OpenAI 官方文档明确扫描 `.agents/skills` |
| Trae CN | 兼容 `.agents/skills` | `.trae-cn/skills` | 用户实测兼容；官方文档目前写 `.trae/skills`，若失效优先排查此处 |

用户确认常用工具（Codex、Trae CN）均兼容 `.agents` 目录。

## 2. 设计目标

把产品从「多 Agent 技能分发器」重构为「**以 `.agents` 为核心的全局/项目技能管理器**」：

- 全局与项目分发统一收敛到 `.agents/skills`。
- 技能组合降为「选择器」，消除双粒度冲突。
- 保留高级用户手动扩展其他全局目录的能力，留后路。

## 3. 核心设计决策

| 决策点 | 结论 | 为什么 / 对用户的影响 |
| --- | --- | --- |
| 技能组合角色 | 降为「选择器」 | 去掉组合的应用/收回与聚合状态，点击只把成员勾入选择集，从根上消除双粒度冲突 |
| 状态唯一事实源 | 单技能在目标里的真实软链接状态 | 只剩一套状态，不再有组合内外矛盾 |
| 项目分发目标 | 固定 `<项目根>/.agents/skills` | 去掉项目维度选 Agent；一键应用即写入该目录 |
| 全局分发目标 | 默认 `~/.agents/skills`，可手动扩展 | 简化日常；保留设置页添加其他全局目录以防未来用不兼容工具 |
| 概念命名 | 「Agent」→「全局目录」 | 分发层面不再区分具体 Agent，概念更干净 |
| 旧目录处理 | 只认 `.agents/skills`，旧目录不扫描、不迁移、不清理 | 实现简单干净；旧链接用户可自行手动删除 |

## 4. 详细设计

### 4.1 技能组合选择器化

**变更：**

- 移除组合的「应用 / 收回」按钮。
- 移除组合的聚合状态（不再显示「未应用 / 已应用 / 部分应用 / 有问题」）。
- 组合保留唯一动作：**「选中组合内全部成员」**——把成员技能加入当前选择集，随后走单技能的应用/收回流程。
- 组合仍是一级管理对象，可创建、编辑、删除、调整成员（与现有约定一致）。

**结果：** 应用/收回只对单技能生效，状态只看单技能在目标里的软链接真实状态。软链接级别的真实冲突（同名内容 / 指向别处）仍如实显示为单技能状态，但不再与组合状态纠缠。

### 4.2 分发模型收敛

**新模型为两个维度：**

| 维度 | 默认目标 | 是否可扩展 |
| --- | --- | --- |
| 全局技能 | `~/.agents/skills` | 设置页可手动添加其他全局目录（如 `~/.claude/skills`） |
| 项目技能 | `<项目根>/.agents/skills` | 不可扩展，固定 |

- **全局维度**：默认只有一个目标 `~/.agents/skills`。高级用户可在设置页手动添加额外全局目录，列表化管理。
- **项目维度**：目标固定为 `<项目根>/.agents/skills`，应用操作只需「选项目 + 选技能」，不再选 Agent。

### 4.3 数据模型调整

> 以下为方向性描述，具体字段在实现阶段细化。

- **全局**：将原 `Agent`（含 5 个默认 Agent）概念替换为「全局目录」（`GlobalDir`）列表，默认一项指向 `~/.agents/skills`，支持手动增删。
- **项目**：`ProjectAgentWorkspace`（项目 × Agent 二维）简化为 `ProjectWorkspace`（仅按项目），目标根固定 `.agents/skills`。
- `TargetStatus` 中与具体 Agent 绑定的字段（`agentId` / `agentName`）在项目维度不再需要；全局维度改为关联「全局目录」标识。
- `SkillStatus` 枚举保留（含 `Conflict`、`Broken` 等），软链接分析逻辑不变。

### 4.4 UI 调整

- 左侧导航：移除「我的 Agent」，全局维度改为「全局技能」入口；「技能组合」入口保留在「技能列表」下方。
- 设置页：原「Agent 管理」改为「全局目录」管理，默认展示 `~/.agents/skills`，可手动添加/移除其他全局目录。
- 状态看板：项目维度按项目分组展示技能在 `.agents/skills` 的真实状态，不再按 Agent 分行。
- 技能组合页：成员区提供「选中全部成员」动作，移除组合级应用/收回与聚合状态徽标。

## 5. 不改动范围（边界）

- 导入流程：本地文件夹 + `.zip` 进主库，不变。
- 主库唯一事实源、软链接分发机制、主库优先覆盖策略，不变。
- 软链接级别的真实冲突检测与提示逻辑，不变。
- 第一版不做覆盖前备份、不做操作日志（沿用现有约定）。
- 项目级管理仍只支持手动添加项目路径，不自动扫描。

## 6. 迁移与兼容

- 旧的项目级目录（`.codex/skills`、`.trae-cn/skills` 等）及其内软链接：**不扫描、不迁移、不清理**。用户可自行手动删除。
- 旧的全局多 Agent 目录：同样不主动处理，新模型默认只管理 `~/.agents/skills`。
- 现有 SQLite 中的 agents 表数据：实现阶段决定是清空重建还是平滑映射为「全局目录」，以最简实现为准。

## 7. 验收标准

- 技能组合无应用/收回按钮、无聚合状态，「选中全部成员」可把成员勾入选择集。
- 单技能可正常应用/收回，状态准确反映 `.agents/skills` 下的真实软链接。
- 项目应用只需选项目 + 选技能，目标路径为 `<项目根>/.agents/skills/<skill-id>`。
- 全局应用默认写入 `~/.agents/skills`；设置页可手动添加并管理其他全局目录。
- 左侧导航与设置页文案使用「全局目录」，不再出现「Agent」分发概念。
- `npm run build`、`cargo check --manifest-path src-tauri/Cargo.toml`、`npm run tauri:build` 通过。
- 常见桌面窗口尺寸下 UI 不重叠、不溢出。
