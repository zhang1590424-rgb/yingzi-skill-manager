# 导入与删除反馈确定性优化设计

日期：2026-06-29

## 1. 背景

当前导入 Skill 成功后，用户需要自己在网格里寻找新技能；删除 Skill 成功后，用户对“刚刚删掉的是不是这个对象”“列表为什么变化”也缺少明确反馈。

这两个问题的本质不是缺少动效，而是操作后缺少上下文交接：系统改变了主库内容，但没有把用户带到变化发生的位置。

## 2. 设计目标

- 导入后让用户立即确认新 Skill 在哪里。
- 删除后让用户确认选中的 Skill 已从主库消失。
- 保持「影子」当前的安静、可信、工具型风格，不增加教学式说明文案。
- 动效只用于表达状态变化，不做装饰。

## 3. 导入成功交互

采用“自动定位 + 打开详情”的方案，但动作要有顺序，避免用户感觉界面突然跳走。

```text
导入成功
→ 导入弹窗关闭
→ 切回「全部技能」
→ 清空搜索、标签和状态筛选
→ 定位到新导入 Skill 卡片
→ 卡片短暂暖色高亮
→ 打开右侧详情抽屉
→ 显示成功 toast
```

### 视觉规则

- 新导入卡片使用淡黄底色和细边框高亮，参考现有 `--accent-yellow-bg` 和 `--accent-yellow-text`。
- 不在卡片上追加“刚刚导入”文字。
- 不在详情抽屉标题下追加“刚刚导入到主库”文字。
- 成功 toast 保留，用于说明结果：已导入、已进入主库、尚未应用到目标。
- 详情抽屉维持现有结构：标题、描述、标签、应用状态、SKILL.md 预览。

### 用户影响

用户不用手动找新 Skill，也不会因为额外说明文字感觉界面在教学。系统通过位置、选中状态和 toast 共同表达“新对象已经进入主库，下一步可以应用到目标”。

## 4. 删除成功交互

删除仍从详情抽屉触发，并保留确认。后端当前会阻止删除仍有启用位置的 Skill，因此 UI 不做自动收回。

```text
点击删除
→ 确认删除
→ 若仍有启用位置，阻断并提示先收回
→ 删除成功后关闭详情抽屉
→ 原卡片位置淡出
→ 网格自然补位
→ 显示成功 toast
```

### 视觉规则

- 删除成功后，详情抽屉按现有关闭动效滑出。
- 被删除卡片使用 `opacity` 和 `transform` 做短暂退出，不使用高度动画。
- 不保留长期占位，不显示撤销入口。
- 成功 toast 文案明确：已删除该 Skill，主库中不再保留。

### 用户影响

用户能确认删除的是刚刚选中的对象。若 Skill 还应用在某个目标中，系统先阻断，让用户先收回，避免主库和目标状态割裂。

## 5. 状态与数据流

### 导入

- 前端在导入前记录已有 `skill.id` 集合。
- 导入命令返回新 `AppState` 后，通过前后差异定位新导入的 Skill。
- 单个文件夹导入时，定位该 Skill。
- zip 批量导入时，如果新增多个 Skill，定位第一个新增 Skill，并在 toast 中说明导入数量。
- 如果无法从差异中定位新增 Skill，只刷新列表并显示成功 toast，不强行打开详情。

### 删除

- 删除前保留待删除 Skill 的 id 和展示名，用于动画与 toast。
- 删除命令成功返回新 `AppState` 后，清空 `selectedId`。
- 列表刷新后移除该 Skill。
- 如果后端返回“仍有启用位置”，保持详情抽屉打开，并通过 toast 提示先收回。

## 6. 动效约束

- 只动画 `opacity` 和 `transform`。
- 导入卡片高亮时长控制在约 1.6s，之后回到普通选中状态或普通卡片状态。
- 详情抽屉继续使用现有 300ms slide-in / 250ms slide-out。
- 删除卡片退出控制在 180-240ms。
- 尊重 `prefers-reduced-motion`：减少或取消滚动与淡入淡出。

## 7. 错误处理

- 导入失败：保留导入弹窗，错误显示在操作上下文内或 toast 中，文案保留具体失败原因。
- 删除失败：详情抽屉保持打开，toast 显示失败原因。
- 删除被阻断：toast 说明“该技能仍有 N 个启用位置，请先收回后再删除”。
- 定位失败：不报错，只退化为刷新列表和成功 toast。

## 8. 验收标准

- 导入单个 Skill 后，自动回到全部技能视图，新 Skill 可见、短暂高亮，并打开详情抽屉。
- 导入后不会在卡片或抽屉中出现“刚刚导入”“刚刚导入到主库”等说明文字。
- 导入后 toast 明确说明 Skill 已进入主库且尚未应用到目标。
- 删除未应用 Skill 后，详情抽屉关闭，卡片消失，toast 明确删除完成。
- 删除仍有启用位置的 Skill 时，操作被阻断，详情抽屉不关闭。
- 搜索、标签筛选、状态筛选不会导致新导入 Skill 被隐藏。
- 窗口 1040x680 到 1440x900 下，抽屉、toast、网格不重叠。
- `npm run tauri:build` 通过，并同步根目录 `影子.app`。
